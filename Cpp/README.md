# Arcscript C++ Interpreter

The C++ interpreter executes Arcscript embedded in the HTML generated by the Arcweave editor. It can evaluate conditions, update variable state, render output, track visits, and emit runtime events.

## Prerequisites

- CMake 3.10 or newer
- A compiler with C++17 support
- Java 11 or newer for running the ANTLR generator
- Python 3 for transforming the C++ grammar
- Network access when CMake downloads the ANTLR C++ runtime and test dependencies

## Building

Generate the ANTLR sources from the repository root, then configure an out-of-source build. These commands remain compatible with the project's minimum CMake version:

```bash
sh generate.sh
mkdir -p Cpp/build
cd Cpp/build
cmake .. -DCMAKE_BUILD_TYPE=Release
cmake --build . --config Release
```

The shared library is written under `Cpp/build/lib/<platform>`. Public headers are copied to `Cpp/build/lib/include`.

On Windows, run `generate.ps1` from the repository root instead of `generate.sh`. Visual Studio and other multi-configuration generators select Release at build time, so `--config Release` is required even when `CMAKE_BUILD_TYPE` is ignored.

With CMake 3.13 or newer, the equivalent root-directory commands are:

```bash
cmake -S Cpp -B Cpp/build -DCMAKE_BUILD_TYPE=Release
cmake --build Cpp/build --config Release
```

## Native C++ API

Use `Arcweave::ArcscriptTranspiler` when integrating directly into a C++ application.

```cpp
#include <any>
#include <iostream>
#include <map>
#include <string>

#include "ArcscriptTranspiler.h"

int main() {
    using namespace Arcweave;

    Variable health;
    health.id = "health-id";
    health.name = "health";
    health.type = VariableType::AW_INTEGER;
    health.value = 75;
    health.defaultValue = 100;

    std::map<std::string, Variable> variables = {
        {health.id, health},
    };

    ArcscriptTranspiler interpreter(
        "current-element-id",
        variables,
        {},
        [](const char* eventName) {
            std::cout << "Arcscript event: " << eventName << '\n';
        }
    );

    const TranspilerOutput result = interpreter.runScript(
        "<pre><code>health -= 10</code></pre>"
        "<pre><code>show(health)</code></pre>"
    );

    std::cout << result.output << '\n';
    std::cout << std::any_cast<int>(result.changes.at("health-id")) << '\n';
}
```

The example renders `<p>65</p>` and records `65` under the stable variable ID `health-id`.

### Variables

Each `Variable` requires the following values:

| Field | Description |
| --- | --- |
| `id` | Stable ID used as the key in returned changes. |
| `name` | Name referenced by Arcscript. |
| `type` | `AW_STRING`, `AW_INTEGER`, `AW_DOUBLE`, or `AW_BOOLEAN`. |
| `value` | Current runtime value. |
| `defaultValue` | Value restored by `reset()` and `resetAll()`. |
| `scope` | Optional component or board scope. An empty string means global. |

Both `value` and `defaultValue` must contain a value. The interpreter throws `RuntimeErrorException` during initialization when either is missing.

### Scoped Variables

Set `scope` to the component or board identifier used in Arcscript:

```cpp
Variable componentHealth;
componentHealth.id = "player-health-id";
componentHealth.name = "health";
componentHealth.type = VariableType::AW_INTEGER;
componentHealth.value = 40;
componentHealth.defaultValue = 50;
componentHealth.scope = "player";

std::map<std::string, Variable> variables = {
    {componentHealth.id, componentHealth},
};

Arcweave::ArcscriptTranspiler interpreter(
    "",
    variables,
    {},
    [](const char*) {}
);

const auto result = interpreter.runScript(
    "<pre><code>player.health = 25</code></pre>"
);
```

Scoped variables are referenced as `<scope>.<name>`. Scope identifiers must be unique wherever the interpreter receives variables.

### Current and Default Values

Current and default values are intentionally separate. This allows state from an earlier invocation to be supplied while preserving the original reset value:

```cpp
Variable score;
score.id = "score-id";
score.name = "score";
score.type = VariableType::AW_INTEGER;
score.value = 25;
score.defaultValue = 10;

Arcweave::ArcscriptTranspiler interpreter(
    "",
    {{score.id, score}},
    {},
    [](const char*) {}
);

const auto result = interpreter.runScript(
    "<pre><code>reset(score)</code></pre>"
);

const int resetValue = std::any_cast<int>(result.changes.at("score-id"));
// resetValue == 10
```

Apply returned changes to your application state before the next interpreter invocation. The interpreter does not persist returned changes into the caller's variable collection.

### Conditions

Condition inputs return a boolean in `TranspilerOutput::result`:

```cpp
const auto result = interpreter.runScript(
    "<pre><code>player.health > 0</code></pre>"
);

if (result.type == Arcweave::InputType::CONDITION) {
    const bool condition = std::any_cast<bool>(result.result);
}
```

### Visits and Events

Pass visit counts by element ID. The current element ID is used by `visits()` when no mention argument is supplied.

```cpp
std::map<std::string, int> visits = {
    {"current-element-id", 3},
    {"other-element-id", 7},
};

Arcweave::ArcscriptTranspiler interpreter(
    "current-element-id",
    variables,
    visits,
    [](const char* eventName) {
        if (std::string(eventName) == "resetVisits") {
            // Reset the application's persisted visit counters.
        }
    }
);
```

`resetVisits()` updates the interpreter's visit state and emits the `resetVisits` event. The callback receives the event name only.

### Error Handling

Invalid Arcscript and runtime failures use separate exception types:

```cpp
const std::string code = "<pre><code>health = 0</code></pre>";

try {
    const auto result = interpreter.runScript(code);
} catch (const Arcweave::ParseErrorException& error) {
    std::cerr << "Invalid Arcscript: " << error.what() << '\n';
} catch (const Arcweave::RuntimeErrorException& error) {
    std::cerr << "Arcscript execution failed: " << error.what() << '\n';
}
```

## Exported Bridge API

`runScriptExport()` provides flat input and output structures for integrations that load the shared library. Although the function uses C linkage, its callback parameter is `std::function`, so the current interface is intended for C++ callers and compatible native bindings rather than direct C callers.

```cpp
#include <iostream>

#include "ArcscriptTranspiler.h"

int main() {
    using namespace Arcweave;

    UVariable health;
    health.id = "health-id";
    health.name = "health";
    health.type = VariableType::AW_INTEGER;
    health.int_val = 75;
    health.default_int_val = 100;
    health.has_default_value = true;

    UTranspilerOutput* result = nullptr;

    try {
        result = runScriptExport(
            "<pre><code>health -= 10</code></pre>",
            "current-element-id",
            &health,
            1,
            nullptr,
            0,
            [](const char*) {}
        );

        for (size_t i = 0; i < result->changesLen; i++) {
            const UVariableChange& change = result->changes[i];
            if (change.type == VariableType::AW_INTEGER) {
                std::cout << change.varId << ": " << change.int_result << '\n';
            }
        }
    } catch (const ParseErrorException& error) {
        std::cerr << "Invalid Arcscript: " << error.what() << '\n';
    } catch (const RuntimeErrorException& error) {
        std::cerr << "Arcscript execution failed: " << error.what() << '\n';
    }

    if (result != nullptr) {
        deallocateOutput(result);
    }
}
```

### Bridge Variable Fields

Set the current and default field matching `UVariable::type`:

| Type | Current value | Default value |
| --- | --- | --- |
| `AW_STRING` | `string_val` | `default_string_val` |
| `AW_INTEGER` | `int_val` | `default_int_val` |
| `AW_DOUBLE` | `double_val` | `default_double_val` |
| `AW_BOOLEAN` | `bool_val` | `default_bool_val` |

Set `has_default_value` to `true` after assigning the matching default field. Set `scope` to a component or board identifier, or leave it as `nullptr` for a global variable.

### Reading Bridge Results

Read the field matching each `UVariableChange::type`:

```cpp
switch (change.type) {
    case Arcweave::VariableType::AW_STRING:
        std::cout << change.string_result;
        break;
    case Arcweave::VariableType::AW_INTEGER:
        std::cout << change.int_result;
        break;
    case Arcweave::VariableType::AW_DOUBLE:
        std::cout << change.double_result;
        break;
    case Arcweave::VariableType::AW_BOOLEAN:
        std::cout << change.bool_result;
        break;
    default:
        break;
}
```

For condition input, check `result->type == Arcweave::InputType::CONDITION` and read `result->conditionResult`.

### Memory Ownership

- Input strings, variable arrays, and visit arrays remain owned by the caller and must stay valid for the duration of `runScriptExport()`.
- The returned `UTranspilerOutput`, output string, change array, variable IDs, and changed string values are allocated by the library.
- Call `deallocateOutput(result)` exactly once for every non-null result.
- Do not separately free fields owned by `UTranspilerOutput`.
- Calling `deallocateOutput(nullptr)` is not supported, so guard nullable result pointers when an exception can occur.

## Running Tests

Configure the project with the C++ test suite enabled, build it, and run CTest:

```bash
mkdir -p Cpp/build
cd Cpp/build
cmake .. -DCMAKE_BUILD_TYPE=Release -DWITH_TEST=ON
cmake --build . --config Release
ctest -C Release --output-on-failure
```

The `-C Release` option is needed by multi-configuration generators and is harmless for single-configuration generators. With CMake 3.20 or newer, CTest may instead be run from the repository root with `ctest --test-dir Cpp/build -C Release --output-on-failure`.

CTest runs the valid-script, member-variable, condition, string-concatenation, runtime-error, and parse-error fixtures independently. It also runs native API tests for reset behavior, current/default values, and variable validation.
